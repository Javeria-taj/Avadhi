Claim Window Navigator

Assembly guide. Every brick, what it does, and the order to click them together.

What this thing does Someone speaks, in Kannada, about a loss that just happened. The system works out which insurance claim clocks are now running, how long is left on each, and what to do right now — then generates the document they carry to the bank. It runs with the network off.

The one idea to hold onto

speech   ↓ [1] ASR — audio → text   ↓ [2] Gemma — text → structured facts   ↓ [3] RULES ENGINE — facts → deadlines   ← no model, no network   ↓ [4] Gemma — explain the result in Kannada   ↓ [5] PDF generation

Stage 3 is the whole argument. The model reports what it heard and explains what was decided — it never decides. Arithmetic on someone's insurance deadline is done by code that returns the same answer every time and cites its source. Say this to the judges in roughly those words.

The bricks

Backend — the engine

A · build first
api/models/schemas.py

Every data shape in the system. This file is the interface contract — freeze it at T+4 and stop changing it. EventReport is what the model extracted; ClaimWindow is what the engine decided. Note what's absent from EventReport: no deadline, no verdict.

A · the critical one
api/rules/engine.py

Pure function. Takes an event and the rules, returns claim windows. No model, no network, no clock reads inside the loop. Handles the three things that break silently: IST timezone, unknown-versus-false, and expired claims that must still be shown.

A
api/rules/loader.py

Reads the rule JSON, and crashes at startup if any rule lacks a source_url. Also holds resolve_relative_datetime() — "last night" becomes a timestamp here, in plain code, with a confidence score. The model is explicitly forbidden from doing date maths.

A · owns the content
data/schemes/*.json

Three rules: PMFBY 72-hour localised calamity, PMSBY 30-day accident, PMJJBY 30-day death. Adding a scheme is a JSON file, not a code change — that sentence is worth real points. Each file carries its citation and a verification note.

A
api/services/asr.py · extract.py · explain.py · document.py

The four model-touching pieces, one job each: audio→text, text→facts, result→Kannada prose, facts→PDF. explain.py falls back to hand-written templates if generation fails, so the countdown always speaks even if the model stalls mid-demo.

A
api/routes/ · api/main.py · api/config.py

HTTP plumbing only — parse, call service, return. main.py has /health (hit it before you walk on stage) and a handler that stops stack traces reaching the screen. config.py validates env at boot and crashes immediately if the model path is wrong, rather than at hour 20.

A · run before wiring anything
tests/test_engine.py

17 tests over boundaries, timezone, unknown-vs-false, and the compounding PMSBY+PMJJBY case. This is the only part of the system where a silent bug costs someone real money. pytest — 67 tests across the engine, working-day arithmetic and case persistence. All green before you touch the UI.

Frontend — the face

B · start here at T+0
ui/lib/mocks.js + ui/lib/api.js

The reason two people can ship this. mocks.js mirrors the backend contract exactly; set NEXT_PUBLIC_USE_MOCKS=true and build the entire interface before the backend exists. Also your emergency demo fallback if inference dies.

B
ui/components/Countdown.jsx

The signature element. Ticks every second so the pressure is felt rather than read, and reports hours — 48 sounds urgent, "2 days" doesn't. Border colour is driven by status, nothing else.

B
ui/components/Recorder.jsx

Tap to start, tap to stop — not press-and-hold, because the user has one wet hand. When the mic fails it names the actual cause (non-HTTPS origin) instead of apologising.

B
ui/components/ClaimCard.jsx

One card per triggered scheme: status badge, Kannada explanation, numbered evidence checklist, reporting channels, document button — and the rule's source citation printed at the bottom, visible. When a judge asks how you know the rule is right, it's already on screen.

B
ui/app/globals.css

No web fonts (offline = blank screen), high contrast (phone in daylight), colour carries status and never decoration. Design reasoning is in the comment block at the top so it survives a tired 3am edit.

both · do this tonight
ui/next.config.mjs · ui/certs/

next.config.mjs rewrites /api/* to FastAPI so the browser only ever talks to one origin — no CORS, and no mixed-content failure when the page is HTTPS. certs/README.md is the microphone setup. Read it before anything else.

Build order

Step 1 · 10 min · do this before anything else

Make the microphone work

getUserMedia is blocked on non-secure origins. The phone opening http://192.168.x.x:5173 gets no microphone and no error message. This has killed more hackathon demos than bad models.

brew install mkcert nss
mkcert -install
ipconfig getifaddr en0          # note your LAN IP
cd ui && mkcert <that-ip> localhost 127.0.0.1
mv <that-ip>+2-key.pem ui/certs/key.pem
mv <that-ip>+2.pem     ui/certs/cert.pem
Verify now, not tomorrow Open the HTTPS URL on the S24 and confirm the mic permission prompt appears. Use the phone's own hotspot — venue Wi-Fi will not work.
Step 2 · 5 min

Prove the engine works with no model at all

python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest                                       # expect 67 passed

MOCK_MODE=true uvicorn api.main:app --host 0.0.0.0 --port 8000
curl localhost:8000/health
Why this matters You now have a working end-to-end product with zero inference. Everything after this is upgrading a system that already runs, not building one that doesn't.
Step 3 · 10 min · B works in parallel from here

Bring up the interface

cd ui && npm install
NEXT_PUBLIC_USE_MOCKS=true npm run dev:https

Open the HTTPS URL on the phone. Full interface, mock data, no backend needed. B can now build for hours without ever blocking on A.

Step 4 · 20 min · use Edge Gallery, not Termux

Measure the phone, and settle the Kannada question

Sideload Google AI Edge Gallery (Apache 2.0, from the google-ai-edge/gallery GitHub releases). It officially supports Gemma 4 and ships a built-in benchmark — ten minutes instead of an hour compiling llama.cpp.

  • Model Management & Benchmark → screenshot the tok/s and memory. That screenshot is your measurements slide.
  • Audio Scribe → speak the Kannada demo line. Clean transcription means ASR_BACKEND=gemma; mushy means whisper. Your T+4 gate, answered before the clock starts.
It is not your backend Edge Gallery is a sandbox with no local API server — your FastAPI app cannot call into it. The real in-app path is LiteRT-LM (MediaPipe's mobile LLM inference is now deprecated), but that means a native Kotlin app, and neither of you is a mobile dev with 36 hours left. Don't take that trade.

So: Path B (kiosk). Model on the M4 under MLX, phone as browser client over the phone's own hotspot. Fully offline. The Edge Gallery benchmark is what substantiates the on-device claim — label it honestly as a benchmark, not as your app.

Step 5 · switch on the real thing

Turn off mock mode

cp .env.example .env        # set MODEL_PATH, MOCK_MODE=false
uvicorn api.main:app --host 0.0.0.0 --port 8000
# and on the UI side, set NEXT_PUBLIC_USE_MOCKS=false
npm run dev

If extraction is poor, the fix is SYSTEM_PROMPT in api/services/extract.py — not the engine. If Kannada ASR is weak, that's the ASR_BACKEND switch, decided by T+4.

When it breaks

SymptomCauseFix
No mic on the phone, no errorNon-HTTPS originStep 1. Always this.
Deadline off by 5½ hoursNaive datetime treated as UTCEverything through _as_ist()
Model returns prose not JSONPrompt drift_strip_fences() already handles fences; tighten SYSTEM_PROMPT
Server won't bootMODEL_PATH wrongDeliberate — config crashes at boot, not at hour 20
Rule loader throwsA rule has no source_urlAlso deliberate. Add the citation.
Inference dies before the demo—MOCK_MODE=true. Full product, no model. Say so honestly if asked.

Before you walk on stage

  • /health returns ok on the actual demo device
  • Airplane mode on, complete run succeeds
  • Backup video recorded and playable offline
  • HDMI adapter tested against the real projector
  • PMFBY helpline number verified on pmfby.gov.in — sources disagree, and it's the one number your product tells people to call
  • Repo public (needed for the Kaggle embed), commits inside the event window
  • Both of you have said the stage-3 line out loud at least five times
